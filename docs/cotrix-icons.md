# Cotrix Application Icons

This document describes how ArtisanZ's application icons are generated from the
Cotrix brand mark, why the legacy macOS `Assets.car` was dropped, and how to
restore the adaptive (liquid glass) icon later on a machine that has Xcode.

## Source of truth

`src/includes/Icons/cotrix-app.svg` — the dedicated **full-bleed** Cotrix
application-icon source (1024×1024). The rounded-square tile fills the entire
canvas edge-to-edge (100% fill), and the "C" mark + twin waves are scaled and
re-centered for app-icon display. This is what `build-icons.sh` rasterizes to
produce `.icns` / `.ico` / `.png`.

> **Why a separate source, not `cotrix.svg`?**
> `src/includes/Icons/cotrix.svg` is a **96×96 toolbar icon**: its inner tile is
> `x=10 y=10 width=76 height=76`, i.e. only ~79% of the canvas with ~11% margin
> around it. That is correct for a small in-GUI toolbar mark, but when used as a
> macOS/Windows/Linux app icon it renders visibly undersized against neighbouring
> app icons (which fill ~88–100% of their tile and are masked by the OS squircle).
> macOS especially expects the artwork to fill the canvas; the OS applies its own
> rounded-corner mask on top. `cotrix-app.svg` exists specifically to fix this —
> it is not used by the GUI and has no test assertions on its geometry.

The original `cotrix.svg` (light) and `white_cotrix.svg` (dark) remain the
toolbar brand marks consumed by `artisanlib/gui_theme.py` (their 96×96 viewBox
geometry is asserted by `test/unitary/artisanlib/test_gui_theme.py`); they are
intentionally **not** used as app-icon sources.

## Generating the icons

From the `src/` directory:

```bash
bash build-icons.sh
```

The script is idempotent and overwrites the following files in place:

| Output | Platform | Sizes embedded |
|---|---|---|
| `src/artisan.icns` | macOS app icon | 16, 16@2x, 32, 32@2x, 128, 128@2x, 256, 256@2x, 512, 512@2x |
| `src/artisan.ico` | Windows app icon | 16, 24, 32, 48, 64, 128, 256 |
| `src/artisan.png` | Linux runtime window icon | 512×512 |
| `src/debian/usr/share/pixmaps/artisan.png` | Debian package pixmap | 512×512 |
| `src/includes/Icons/artisan-trayicon.svg` | macOS tray / notification | 22×22 viewBox |
| `src/includes/Icons/artisan-trayicon-large.svg` | macOS tray (HiDPI) | 22×22 viewBox, heavier strokes |

### Toolchain

| Tool | Used for | Comes from |
|---|---|---|
| `qlmanage` | SVG → PNG raster | macOS (built-in) |
| `sips` | PNG resize / format | macOS (built-in) |
| `iconutil` | iconset ↔ icns | macOS (built-in) |
| Pillow | assembling Windows `.ico` | `src/.venv` (`pip install Pillow`) |

### Out of scope

These icons are **not** regenerated by `build-icons.sh` because the Cotrix
rebrand scope is limited to the main app icon and tray icon:

- Document-type icons: `artisanProfile.icns/.ico`, `artisanAlarms.*`,
  `artisanPalettes.*`, `artisanSettings.*`, `artisanWheel.*`, `artisanTheme.*`.
- In-GUI brand SVGs: `cotrix.svg`, `white_cotrix.svg` (96×96 toolbar marks
  consumed by `gui_theme.py`; their contents are asserted by
  `test/unitary/artisanlib/test_gui_theme.py`).
- Web/report favicons under `src/includes/` (`favicon*`, `apple-touch-icon.png`,
  …) — used by HTML report templates, not by the app bundle.

## Why `Assets.car` was removed

macOS Tahoe (and later) supports *adaptive* app icons rendered from a compiled
asset catalog (`Assets.car`). Upstream Artisan shipped `src/Assets.car`
containing an `artisan-liquid-glass` icon stack, wired up via
`Info.plist`'s `CFBundleIconName = 'artisan-liquid-glass'`.

Compiling an asset catalog requires Apple's `actool`, which is **only available
with a full Xcode install** — the Command Line Tools alone are not enough:

```
$ actool ...
xcode-select: error: tool 'actool' requires Xcode, but active developer
directory '/Library/Developer/CommandLineTools' is a command line tools instance
```

Because the build environment for ArtisanZ does not have Xcode, the adaptive
icon could not be regenerated with the Cotrix mark. Rather than ship a stale
upstream `Assets.car` (which would make macOS Tahoe keep showing the old
Artisan "A" liquid-glass icon even after the rebrand), the rebrand drops it:

1. `src/artisan-mac.spec` — removed `(r'Assets.car', '.')` from `DATA_FILES`,
   so the file is no longer bundled into `Artisan.app/Contents/Resources/`.
2. `src/artisan-mac.spec` — commented out `'CFBundleIconName':
   'artisan-liquid-glass'` in the generated `Info.plist`, so macOS falls back
   to `CFBundleIconFile = artisan.icns` (the new Cotrix icon).

The result: every supported macOS version now shows the Cotrix icon, at the
cost of losing the Tahoe-only adaptive/liquid-glass treatment. The static
`.icns` is still high quality at all resolutions from 16×16 up to 1024×1024.

## Restoring the adaptive (liquid glass) icon later

If you have a machine with full Xcode and want the adaptive icon back, you can
rebuild `Assets.car` from a Cotrix asset catalog. High-level steps:

1. Create an Xcode asset catalog:

   ```
   src/CotrixIcon.xcassets/
       Contents.json
       AppIcon.appiconset/
           Contents.json
           icon_1024.png        # 1024×1024 master PNG (regenerate via build-icons.sh)
   ```

   `AppIcon.appiconset/Contents.json` should declare a single universal
   1024×1024 image (the modern single-size catalog format that macOS Tahoe
   uses for adaptive icons):

   ```json
   {
     "images" : [
       { "filename" : "icon_1024.png", "idiom" : "universal", "platform" : "ios", "size" : "1024x1024" }
     ],
     "info" : { "author" : "xcode", "version" : 1 }
   }
   ```

2. Compile it with `actool`:

   ```bash
   cd src
   xcrun actool --output-format human-readable-text \
       --compile . \
       --minimum-deployment-target 13.0 \
       --platform macosx \
       CotrixIcon.xcassets
   # produces ./Assets.car
   ```

3. Re-enable bundling in `src/artisan-mac.spec`:
   - Add `(r'Assets.car', '.')` back to `DATA_FILES`.
   - Uncomment the `'CFBundleIconName'` line, changing the value to match the
     new iconset name (e.g. `'AppIcon'`).

4. Rebuild the macOS `.app`. Verify in Finder / Dock that the adaptive icon
   appears.

## Rollback

To revert the whole rebrand and restore the upstream Artisan icons:

```bash
cd src
git checkout -- artisan.icns artisan.ico artisan.png \
    debian/usr/share/pixmaps/artisan.png \
    includes/Icons/artisan-trayicon.svg \
    includes/Icons/artisan-trayicon-large.svg \
    artisan-mac.spec
```

(`Assets.car` itself was never deleted — only its bundling reference was, so it
remains in the working tree and `git checkout` is not needed for it.)
