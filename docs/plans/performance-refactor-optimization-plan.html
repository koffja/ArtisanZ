ArtisanZ 高效能重構優化路徑計畫

以可測量、可回退、低風險方式，從現有 Python / PyQt6 / matplotlib 架構逐步走向更高效能的混合架構。

Goal: 建立一份可執行的高效能重構路線圖，先保住 ArtisanZ 現有功能與打包能力，再逐步驗證 OMP/threadpool、scipy/math 隔離、Modbus 邊界抽象、Rust/PyO3/Tauri 原型與長期 UI 遷移。

Architecture: 短期保留 PyQt6 主應用與 matplotlib 交互模型，先把可量測熱點隔離出來；中期在 scipy/RoR/Modbus 等邊界建立穩定接口；長期只在原型證明收益後，才考慮 Rust/Tauri/uPlot/egui/Slint 類替代方案。

Tech Stack: Python 3.12+ / PyQt6 / PyInstaller / numpy / scipy / matplotlib / pymodbus / threadpoolctl / Rust / PyO3 / Tauri / uPlot / egui / Slint。

文件位置: docs/plans/performance-refactor-optimization-plan.html

撰寫日期: 2026-06-06

一、核心判斷

推薦策略: 不從「換語言」開始，而從「建立可測量邊界」開始。先讓目前 Python/Qt 版本可穩定 benchmark 與打包，再逐步隔離熱路徑；只有當 Rust/Tauri 原型在真實資料與交互複雜度下明顯勝出，才擴大遷移範圍。
  • 完整 Rust 重寫不建議作為第一步。 現有應用不是單純 GUI，而是 PyQt6、matplotlib QtAgg、設備通信、即時採樣、報表與狀態機深耦合系統。
  • matplotlib 替換難度高。 它不只畫線，還承擔拖拽標註、pick/mouse events、座標轉換、blit、PDF/export 與 QtAgg 交互。
  • scipy API 面有限，但所在路徑重要。 主要集中於 RoR 平滑、樣條、curve fitting、PID/filter 等核心體驗路徑。
  • Modbus-only 新產品可行，但必須收窄。 若只保留 Modbus、基礎曲線、profile 儲存/載入，Rust/Tauri 原型有驗證價值；若複製 Artisan 全功能，會重新接近全量重寫。

三、需要避免的過度推論

不要把估計值當結論。 「刪 OMP 一行可快 2-4 倍」、「Tauri/uPlot 必然 10x」、「Rust 0 抖動」、「Slint 可簡單替換 Qt」都應降級為假設，必須用 ArtisanZ 真實資料與真實交互複雜度驗證。
  • OMP: 放開 BLAS/OpenMP 線程可能提高批量計算速度，也可能增加 UI 卡頓與採樣 jitter。
  • PyO3: 可加速單一熱函數，但不會消除 CPython、PyQt6、numpy、scipy、matplotlib 的啟動成本。
  • Tauri/uPlot: uPlot 對時序曲線很快，但不內建 Artisan 現有 annotation、拖拽、pick event、PDF/export 等完整交互。
  • egui/Slint: egui 官方承認非 native-looking 且 immediate mode 有 layout/CPU 取捨；Slint 是否適合商用與複雜圖表需重新驗證授權和能力。

四、分階段實施計畫

Phase 0：建立性能與打包基線

目標: 在不修改功能的前提下，建立啟動、打包、採樣、繪圖、RoR/math 的可重複 benchmark。

涉及文件: src/artisan.py, src/artisan-mac.spec, src/artisan-win.spec, src/pyinstaller_hooks/rthooks/pyi_rth_mplconfig.py, src/pyproject.toml。

  • [ ] 記錄 Python 版本、PyInstaller 版本、PyQt6、numpy、scipy、matplotlib、pymodbus 版本。
  • [ ] 量測 source run 啟動時間、macOS .app 啟動時間、Windows portable 啟動時間。
  • [ ] 用 python -X importtime -c "import matplotlib.pyplot" 量測 matplotlib 冷啟動成本。
  • [ ] 用固定 profile 資料量測 RoR / smooth / spline / curve_fit 的 p50/p95 耗時。
  • [ ] 記錄採樣 jitter、UI redraw 時間、CPU%、記憶體峰值、打包產物大小。

驗收標準: 產出一份 baseline 表格；後續任何優化都必須與此表對比，不能只靠主觀體感。

Phase 1：低風險 Python / PyInstaller 優化

目標: 不改 UI 與設備行為，先處理啟動與打包中最容易驗證的成本。

涉及文件: src/artisan.py, src/artisanlib/canvas.py, src/conftest.py, src/artisan-*.spec。

  • [ ] 保留 OMP_NUM_THREADS=1 作為控制組，新增實驗組而不是直接刪除。
  • [ ] 評估引入 threadpoolctl，在 RoR/spline/fit 熱路徑周圍局部限制 BLAS/OpenMP 線程。
  • [ ] 檢查所有函數體內 scipy import，評估是否提升為集中 lazy loader，避免重複初始化。
  • [ ] 分別比較 PyInstaller onedir / onefile 啟動時間；macOS 優先驗證 onedir .app。
  • [ ] 驗證 MPLCONFIGDIR 與字體快取行為，避免 frozen app 每次重建字體 cache。

驗收標準: 啟動時間或打包體積有可量化改善；採樣 jitter 與 UI redraw 沒有退化；所有最小回歸測試通過。

Phase 2：數學 / 濾波 / RoR 邊界隔離

目標: 先把 math hot paths 從 canvas.py 的巨大上下文中切出穩定接口，為 PyO3/Rust 或純 Python 優化做準備。

涉及文件: src/artisanlib/canvas.py, src/artisanlib/pid.py, src/artisanlib/filters.py, src/artisanlib/transposer.py, src/test/unitary/artisanlib/test_canvas.py, test_pid.py, test_filters.py。

  • [ ] 建立輸入/輸出 fixture：時間序列、ET/BT、RoR、背景曲線、designer 曲線。
  • [ ] 對 savgol_filter、UnivariateSpline、curve_fit、polyRoR、arrayRoR 建立一致性測試。
  • [ ] 將純計算函數搬入較小模組，保持 canvas.py 只負責 UI/狀態調用。
  • [ ] 比較三種策略：現有 scipy、局部 threadpoolctl、PyO3/Rust prototype。
  • [ ] 確認 .alog、RoR、曲線輸出在允許誤差內一致。

驗收標準: 任何替代實作都必須通過數值一致性測試；若 PyO3 加速比不足以抵消打包複雜度，停止擴大 Rust 範圍。

Phase 3：Modbus / Serial 設備邊界抽象

目標: 在 Python GUI 不動的前提下，明確設備通信接口，優先處理 Modbus-only 可遷移子集。

涉及文件: src/artisanlib/async_comm.py, src/artisanlib/modbusport.py, src/artisanlib/s7port.py, src/artisanlib/comm.py, src/test/unitary/artisanlib/test_async_comm.py, test_modbus.py, test_s7port.py。

  • [ ] 將 AsyncLoopThread 的生命週期、send/read/reconnect 行為寫成契約。
  • [ ] 梳理 Modbus RTU/TCP/UDP、register segment、BCD、float endian、timeout、cache、reconnect 行為。
  • [ ] 定義 Python adapter 接口，使現有 UI 只依賴穩定抽象，不直接依賴 pymodbus 細節。
  • [ ] 建立 Modbus simulator 測試與長跑測試，覆蓋 noisy line、timeout、disconnect/reconnect。
  • [ ] 明確暫不遷移範圍：S7、Phidget、Yoctopuce、BLE、plus/cloud、報表與完整 profile import/export。

驗收標準: Modbus 行為在 Python adapter 後保持一致；test_async_comm/test_modbus 通過；長跑採樣 jitter 無退化。

Phase 4：PyO3 / Rust 熱路徑原型

目標: 只針對邊界清晰、測試充分的熱函數做 Rust 原型，不碰 UI 主架構。

候選: RoR 向量計算、濾波器、樣條/插值替代、Modbus frame parsing、BCD/endian 轉換。

  • [ ] 使用 maturin 建立最小 PyO3 module，先只導出一個純函數。
  • [ ] 用同一 fixture 對比 Python 版與 Rust 版輸出。
  • [ ] 用 pytest-benchmark 或等價工具比較 p50/p95。
  • [ ] 在 PyInstaller frozen app 中驗證 Rust extension 可被收集與載入。
  • [ ] 計算維護成本：編譯鏈、wheel、ABI、macOS 簽名、公證、Windows VC runtime。

驗收標準: 單點加速顯著、輸出一致、打包可控，才允許第二個函數進入 Rust；否則保留 Python 優化。

Phase 5：Modbus-only Rust/Tauri 最小產品原型

目標: 不複製 Artisan 全功能，只做「連接 Modbus → 即時採樣 → 曲線顯示 → 儲存/載入 profile」的最小閉環。

候選技術: Tauri 2 + Rust backend + uPlot 前端；或 egui/Slint 作對照 demo。

  • [ ] 建立最小 Tauri app，記錄 release 體積、啟動時間、首屏時間。
  • [ ] 用真實 ArtisanZ profile 資料量測 1萬/10萬點曲線首幀、zoom、pan 與 CPU%。
  • [ ] 實作 Modbus simulator 連接，記錄採樣頻率與 jitter。
  • [ ] 實作 profile save/load 的最小格式，與 ArtisanZ 現有輸出做一致性比較。
  • [ ] 不實作 S7/Phidget/Yocto/BLE/WebLCD/plus/cloud/PDF/report，避免範圍失控。

驗收標準: 原型在啟動時間、包體、曲線交互、採樣穩定性至少兩項顯著優於現有 PyQt/matplotlib，且不犧牲最小產品需求，才進入產品化討論。

Phase 6：長期 UI / 繪圖遷移決策

目標: 根據 Phase 5 真實原型數據，而不是預設偏好，決定是否遷移 UI。

  • [ ] 列出現有 matplotlib 不可降級交互：拖拽標註、pick events、annotation、axis transform、blit、PDF/export、比較器、多背景曲線。
  • [ ] 分別評估 uPlot、egui、Slint、保留 PyQt/matplotlib 四種方案的功能缺口。
  • [ ] 若功能缺口過大，保留 PyQt 主體，只遷移 math/device core。
  • [ ] 若原型收益明顯，建立獨立產品線，不在原 ArtisanZ 主分支直接重寫。

驗收標準: 有數據、有功能差異表、有維護成本表；沒有這三項，不做 UI 遷移決策。

六、外部技術參考約束

  • PyInstaller: onefile 啟動慢有結構性原因；macOS onefile + .app 方向不應作為主方案。PyInstaller 版本也關聯 scipy/numpy hooks 與安全修復。
  • threadpoolctl: 可控制 BLAS/OpenMP thread pools，但限制是進程全局生效；OpenMP nesting 與多 runtime 共存需小心。
  • PyO3: 適合邊界清楚的熱函數，需同時驗證 Rust 端測試、Python 端 pytest、maturin/wheel、PyInstaller 收集與跨平台簽名。
  • Tauri: 小包體與原生 webview 是優勢，但 Windows WebView2、Linux webkit2gtk、前端 bundle、原生菜單與 HiDPI 行為都需原型驗證。
  • uPlot: 對大規模時序線圖有明顯性能潛力，但不提供 Artisan 目前完整交互模型；需 plugin 或重寫交互。
  • egui: 即時模式簡潔但非 native-looking，長 scrollback 與每幀 layout 有 CPU 取捨。
  • Slint: 需重新查明當前商用授權與複雜圖表能力；不能只因 Rust 原生就假設適合。

七、建議優先順序

  1. 先做 Phase 0。 沒有基線就沒有優化，任何「可能更快」都不應進入主分支。
  2. 再做 Phase 1。 懶載入、MPLCONFIGDIR、打包模式、threadpoolctl 是低風險高回報候選。
  3. Phase 2 與 Phase 3 並行準備。 math 與 Modbus 是最清楚的可切邊界，優先於 UI 重寫。
  4. Phase 4 僅限單點原型。 PyO3 先證明一個函數真的值得，再擴大。
  5. Phase 5/6 作為產品策略，不作為維護性重構。 Rust/Tauri 是新產品或長期方向，不應直接替代當前 ArtisanZ 主線。
